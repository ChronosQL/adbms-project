# Anti-Slop UI Design & Engineering Skill — Ceylon Best Tours

This skill provides an actionable, 6-phase engineering workflow for building and refining user interfaces in the **Ceylon Best Tours** repository. It ensures that every screen feels crafted by a senior product designer rather than generated by a generic AI template.

---

## The Ceylon Best Tours Visual Identity

Always ground design decisions in the project's single source of truth: [`frontend/src/components/pages/Admin/AdminDashboard/adminTheme.jsx`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/pages/Admin/AdminDashboard/adminTheme.jsx).

### 1. Brand Palette & Color Tokens
* **Primary Brand Accent (`BRAND.coral` - `#EF8354`)**:
  * Used for: Primary call-to-action buttons, active navigation indicators, review star ratings, status highlights.
  * Hover state: Slightly deeper tone (`#d96f42` or darkening with filter).
* **Deep Gunmetal (`BRAND.gunmetal` - `#2D3142`)**:
  * Used for: Primary text headings, dark-mode root background (`pageBg`), high-contrast structural accents.
* **Payne's Gray (`BRAND.payneGray` - `#4F5D75`)**:
  * Used for: Secondary text, subtitles, table column headers, metadata badges.
* **Silver / Neutral (`BRAND.silver` - `#BFC0C0`)**:
  * Used for: Crisp 1px borders, subtle separators, input borders in light mode.
* **Surface White (`BRAND.white` - `#FFFFFF`)**:
  * Used for: Elevated cards, dropdown menus, modal backgrounds in light mode.
* **Semantic Status Roles (`STATE`)**:
  * Success: `#2F9E44` (Confirmed, Accepted, Approved, Paid)
  * Warning: `#E3A857` (Pending, Quoted, Needs Attention)
  * Danger: `#E0483B` (Cancelled, Rejected, Error)
  * Info: `#6366F1` (Tour Started, Information notices)

### 2. Typography Rules
* **Headings (`FONT.heading`)**:
  * Font Family: `'Montserrat', 'Segoe UI', sans-serif`
  * Weights: Bold (`700`) and Extrabold (`800`).
  * Used for: Page titles, section headers, key stat figures, tour titles.
* **Body Copy & Controls (`FONT.body`)**:
  * Font Family: `'Open Sans', 'Segoe UI', sans-serif`
  * Weights: Regular (`400`), Medium (`500`), Semibold (`600`).
  * Used for: Paragraphs, input labels, table cell content, button labels, badge text.

### 3. Iconography & Interaction Rules
* **Strict Iconography**: Always import and use vector icons from `lucide-react` (or `react-icons`).
* **Emoji Prohibition**: **NEVER** use emojis as interface action buttons or icons (e.g. never use 🚗, ✏️, 🗑️ as buttons). Emojis may only appear in conversational customer feedback or celebratory empty states.
* **Action Buttons**: Must feature explicit hover and focus transitions (`transition-colors duration-150` or `transition-all 0.2s ease`).

## The 6-Phase Anti-Slop Implementation Workflow

When asked to create, modify, or enhance any UI in this project, execute these six phases in order:

### Phase 1: Understand
1. **Identify the View Scope**:
   * **Admin Portal** (`/admin/*`): Lives inside [`AdminLayout.jsx`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/pages/Admin/AdminDashboard/AdminLayout.jsx) with dark/light mode context (`useOutletContext()?.dark`), horizontal sticky nav, and `adminTheme`.
   * **Public / Customer Site**: Wrapped in [`SiteLayout`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/App.jsx) with global `Navbar` and `Footer`.
2. **Inspect Existing Sibling Pages**: Before drafting layout, inspect how similar features are built (e.g. [`ApproveBookings.jsx`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/pages/Admin/ApproveBookings/ApproveBookings.jsx) for tables, [`VehicleCategory.jsx`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/pages/Site/VehicleCategory/VehicleCategory.jsx) for card showcases).
3. **Check Shared Components**: Inspect [`frontend/src/components/common/`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/common/) for available components (like `Pagination.jsx`).

### Phase 2: Plan Layout & Interactions
1. **Avoid Generic AI Tropes**:
   * No full-screen purple/pink radial gradients.
   * No floating blurry ambient blobs.
   * No nested cards with triple shadows.
2. **Define View Structure**:
   * Clear contextual header with summary counter (e.g. `X total · Y pending`).
   * Filter / search bar with responsive wrapping.
   * Main content: clean table with zebra striping OR responsive grid (`grid-cols-1 md:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 gap-6`).
   * Docked or bottom-anchored pagination controls.
3. **Plan the 4 Core Data States**:
   * *Loading*: Coral spinner or pulse skeleton cards.
   * *Empty*: Informative message with contextual icon and call-to-action button.
   * *Error*: Non-blocking inline banner or toast notification.
   * *Populated*: Data rows with subtle hover highlight.

### Phase 3: Implement Clean React Components
1. **Import Theme Tokens**:
   ```javascript
   import { BRAND, FONT, STATE, getTheme } from "../AdminDashboard/adminTheme";
   ```
2. **Reuse Common Components**:
   * Import [`Pagination.jsx`](file:///c:/Users/Lenovo/Desktop/Projects/personal/data_engineering/TechNova/frontend/src/components/common/Pagination.jsx) whenever a listing exceeds 6–10 items:
   ```javascript
   import Pagination from "../../../common/Pagination";
   ```
   * Pass `scrollToRef={false}` when pagination is embedded inside a split-screen or dashboard sidebar to prevent jarring window jumps.
3. **Synchronize Filters with Pagination**:
   * Whenever search text, tab selection, or status filters change, reset `page` to `1`.
4. **Responsive Integrity**:
   * Use Tailwind breakpoints (`sm:`, `md:`, `lg:`, `xl:`) to ensure no horizontal overflow on mobile screens.

### Phase 4: Inspect Rendered UI
1. Check visual alignment, text contrast, whitespace hierarchy, and border radius consistency.
2. Confirm dark/light theme responsiveness in Admin views (`t.cardBg`, `t.cardBorder`, `t.textPrimary`, `t.textSecondary`).
3. Verify that interactive elements have adequate tap targets on mobile (minimum 44x44px).

### Phase 5: Validate
1. Run the frontend production build to verify JSX syntax and imports:
   ```powershell
   npm run build --prefix frontend
   ```
2. Run backend regression tests if the UI interacts with API endpoints:
   ```powershell
   npm test --prefix backend
   ```

### Phase 6: Refine
1. Fix any truncation, text overflow, or unstyled default states.
2. Ensure keyboard navigation works (Tab / Enter on buttons and inputs).
3. Confirm that no unused styles, temporary console logs, or dead imports remain.
